# Implementation plan, 2026-11-11

What this implements: the backlog from `docs/investigation-2026-11-11.md` (items 1, 2, 4, 5, 6, 7, 8) and the takeaways from
`docs/atomic-agent-comparison.md` §5 (1 to 7). What it leaves out, by decision: Haiku 5.5 as a child harness (backlog 3),
an atomic-agent child adapter, the scout/read-only mode, and a mode-ON hook that pre-runs gruntly (speculative; needs an
explicit opt-in; revisit after the M4 numbers). Result aging does not apply to a two-turn parent.

The shape every change serves: **one call, one block, two parent API calls, no parent context growth beyond the block,
the facts decided by gates written before the work, and honest accounting.** Measured basis: a delegation already takes
exactly 2 parent calls (−11% in a fresh session); the model (`bench/cost_model.py`) gives −35% to −67% in deep sessions on
4- to 8-turn tasks, and every losing arm lost on takeovers, follow-ups and re-reads.

## Invariants (each gets a test)

| # | Invariant | Where it is enforced after this plan |

## M2. The holdout in the same call; an optional final review (backlog 1, takeaways 2 and 3)

### 2.1 `gruntly agent-run --holdout PATH [--holdout-cmd CMD] 'request'`
- Parser (`cli.py:885-899`): `--holdout` (repeatable) and `--holdout-cmd`. The content comes either from stdin (the
  heredoc form, which keeps the whole delegation inside one Bash call: `gruntly agent-run --holdout tests/holdout_paginate.py 'fix …' <<'EOF' … EOF`)
  or from a file the parent wrote with its Write tool in the same message; gruntly writes PATH (untracked) when it does not
  exist. `spec._check_holdout` (`spec.py:171`) already demands it inside the repo.
- Attach: a helper `_holdout(a, root)` → `{"files": [...], "cmd": CMD or "<python> -m pytest -q PATH…"}` (python from
  `do.python_cmd`) set as `raw["holdout"]` in every branch of `_agent_one` (`cli.py:134-200`) before `build_spec`;
  `--continue` re-attaches it from the stored `spec.json`. For `--supervised`, the holdout runs once as the final check in
  `_finish` (early steps are expected red) and fails the task if red: the reviewer's approval cannot override it (I3).
- Gate: `_holdout_gate` (`runner.py:238`) exists (copy in, run, remove; `GATE_PRIORITY` already orders it). A holdout failure
  ends the run as `failed (holdout)`: the child never sees the test or its output (otherwise it becomes acceptance the child
  can game). The parent gets the failing tail and decides (`--continue` in its own words).
- Block: `holdout: pass (tests/holdout_paginate.py, kept; add it to the suite or delete it)` after `tests:`; on failure the
  usual failed block with the tail. The file stays in the working tree, untracked.
- Verify the child's worktree never contains the file (`worktree.create`, `worktree.py:106`, from `base: working-tree`):
  a test asserts it.
- Teach it (skill, HINT_ON, GUIDE, CLI policy): "When you know a behaviour the tests do not check, write it as a holdout
  test in the same call (heredoc form). It costs output tokens only (about $0.003 for 30 lines) and is the one check that
  catches a pass the hidden tests would fail (1 of 5 runs on 2026-11-11)."
- Tests (fake child): holdout pass → the line; holdout fail → `failed (holdout)`, worktree never had the file; stdin
  content written to PATH; `--continue` keeps the holdout.

### 2.2 `agent-run --review [model[:effort]]`: one review outside the session, one automatic re-dispatch
- After a passed run, one `supervise.reviewer_call` with the stable prefix (rules, CLAUDE.md/AGENTS.md, the request) as the
  system prompt file (3.1) and the final diff plus the child's report as the message; verdict APPROVE or FIX.
- On FIX, if time remains in the call: one automatic `--continue` carrying the reviewer's words (atomic's "a failed part goes
  back out with the reviewer's words", capped at one), then a second review. The block shows both verdicts and the cost:
  `review (sonnet:low, $0.0072, outside your session): APPROVE: …`. A FIX that stands after the re-dispatch leaves the status
  `passed` (the gates passed) with `review: FIX: …` as line 3, so the parent forwards it rather than re-reads the code.
- One review is a one-shot call: caching off (the probe's setting, measured $0.0072 against $0.011 with caching on).
- Default off; the benchmark (M4) measures it as an arm.
- Tests: an injected fake reviewer: APPROVE; FIX → continue → APPROVE; FIX → FIX reported honestly; out of time → review
  skipped and said so.

### 2.3 `agent-run --samples N`: best-of-N children, the gates pick (related work, row 1)
- Why: repeated sampling from a cheap model with a real verifier beats one sample from a strong model at lower cost
  (Large Language Monkeys: five DeepSeek samples beat one Claude/GPT sample at over 3x lower cost; S*; CodeMonkeys), and
  with a free child the N samples cost wall time, not dollars. Selection is the known bottleneck (CodeMonkeys: random
  45.8% vs oracle 69.8%), and imperfect verifiers prune good candidates at large N (Scaling Flaws), so N stays small and
  the selectors are the real tests and the parent's holdout, never child-written tests alone (I3).
- The laptop constraint comes first: gruntly's centre is one local model on a student's machine, and one local server
  answers one request at a time. So locally there is no "N children at once": N samples run one after another, stop at
  the first pass, use no extra memory, and cost N× wall time. The gain over today's feedback retry is only that each
  sample is independent, so locally `--samples` stays opt-in and the default is 1. The parallel form exists only on a
  hosted provider the person has configured (`_runs_in_parallel`, `PARALLEL_MAX`), where the literature's numbers come from.
- Design: `--samples N` (default 1; a hosted provider may set `samples = 3` in `.gruntly.toml`) prepares N runs of the
  same spec in N worktrees (`runner.prepare` per sample), each with its gates and the holdout. Selection: the first
  candidate that passes everything is applied (locally that ends the sequence); several pass → the smallest diff
  (insertions + deletions), ties → earliest; none pass → today's feedback retry on the candidate with the fewest failing
  tests, the others discarded. Block: `samples: 3 run, 2 passed, applied #2 (smallest diff, 14 lines); #1 passed with
  41 lines; #3 failed acceptance`. The accounting line shows N× child work and the wall time.
- Tests (fake child with a per-sample outcome script): 0/3, 1/3, 2/3 pass with the smallest-diff choice; worktrees of
  the losers removed; `--samples 1` unchanged.
- Measure before shipping as default anywhere: `bench/run_child_bench.py` (hidden tests, no parent) at N=1 and N=3 with
  Laguna (parallel, hosted) and Qwen 9B (sequential, local) on the ten small tasks; report pass rate, false passes and
  wall time. Hosted default 3 only if hidden-test pass rises without a false-pass rise; local default stays 1 unless the
  sequential form beats today's retry by enough to pay for its wall time, which the bench will show either way.

## M3. Supervised: cached reviewer, speed-sized budgets, large tasks only (backlog 5, 8; takeaways 4, 7)

### 3.1 Byte-stable reviewer prefix through `--system-prompt-file` (I4)
- `reviewer_call` (`supervise.py:87-99`) takes a `system_file`: `--system-prompt-file PATH` (present in this build:
  `claude --help` lists `--system-prompt[-file]`) holding `REVIEWER_SYSTEM` plus the stable context (`context()`:
  rules, CLAUDE.md/AGENTS.md, task, check) and, for step reviews, the approved plan. Written once per task to
  `.gruntly/supervised/<id>/system-plan.txt` and `system-steps.txt`; bytes never change afterwards. This also removes the
  Windows `.cmd` quoting rule and the 32k command-line limit that kept the stable context out of the system prompt.
- Caching per call: the plan review (Sonnet, one call) with caching off; step reviews (Haiku, two or more calls) with caching
  on. `costs.json` gains per-call `{model, cost, input, cache_read}` from the `-p` JSON result, so the block's reviewer line
  is measured, not assumed.
- Test (`tests/e2e/test_supervise.py`): a fake `call` records the system file's bytes; all step reviews of one task are
  identical; the plan file differs from the step file only by the plan section.
- Done when a live supervised run on `inventory_reorder` shows `cache_read` on reviews 2..n and the per-review cost against
  the 2026-11-10 probe (Haiku $0.0005 to $0.0007) is reported, whichever way it goes. If the reads do not appear (Claude
  Code's cache breakpoints), fall back to caching off everywhere and say so.

### 3.2 Worker time from measured speed (takeaway 7, I7)
- Today `STEP_BUDGET_S = 600` (`supervise.py:32`), `budget_s` 900 and `no_progress_s` 120 (`spec.py:33-34`) are constants.
  Measured: Laguna 31 to 45 requests per step, 2 to 13 minutes per step, one step killed at 600 s.
- New `src/gruntly/speed.py`: from the run index (`store.read_index()`: `harness`, `model`, `wall_s`,
  `child_usage.requests`), the last 20 runs of this harness/model give `s_per_request` (median) and `requests_p90`.
  Step budget = clamp(1.5 × requests_p90 × s_per_request, 300, 1800); for `agent-run`, min(that, max_block − 30).
  `no_progress_s` = clamp(3 × s_per_request, 60, 300). No history: today's values. `gruntly doctor` and `gruntly stats` print
  the numbers.
- Tests (`tests/unit/test_speed.py`): synthetic index: fast child → the 300 s floor; slow → the 1800 s cap; no history → defaults.

### 3.4 One call, all results inside it (takeaway 1, I1)

### 3.5 A stronger child before the parent: the escalation chain (related work, row 3)
- Why: cascades that try the cheapest model first and escalate on failure match stronger single models at a fraction of
  the cost (EcoAssistant 80% at 5.90 vs GPT-4 59% at 13.77; AI Agents That Matter's escalation baseline; AutoMix; RouteLLM).
  gruntly's `failed` today goes straight to the parent, the most expensive possible next step.
- The laptop constraint again: escalation never needs a second local model (a student's laptop holds one). The rung
  that works everywhere escalates the **method**, not the model: the same local child, a fresh worktree, the failure
  bundle and the previous child's handoff notes as guidance (`runner.execute(..., guidance=)` exists), the scope widened
  from the named files to the whole project except the check's own files (the `--explore` scope) and the whole suite as
  the check. It costs child time only. A second rung, a hosted child, exists only where the person has configured a
  hosted provider (`[escalate] chain = ["nvidia"]`); it is never the default and never required.
- Design: on `failed`, `escalate` or `timeout`, one escalation per request, inside the same call when time allows: the
  method rung first; the hosted rung only if configured and the method rung failed too. The block says
  `escalated: named files failed (acceptance) → wider scope passed` or `… → hosted poolside/laguna-xs-2.1 passed`, and the
  accounting line shows every run. The parent's own takeover stays the last step (I2).
- Tests: fake children with scripted outcomes: fail → pass on the method rung, fail → fail (honest block), hosted rung
  only when configured; the time budget split between the runs.
- Measure: child-only bench, pass rate and false passes with and without escalation; later the takeover column in M4.

### 3.6 `agent-run --red-first`: a failing test from a separate child, never proof (related work, row 4)
- Why: a test written by a fresh child that never sees the fix catches "nothing to do" and gives the fix child a target
  (Agentless reproduction tests; UTGen; AgentCoder's separate test designer); LLM self-evaluation of code is unreliable
  (UTGen), so it stays unproven in the block unless a holdout or an existing test covers the same behaviour.
- Design: optional flag (and a `.gruntly.toml` default). Step 1: a child in a read-only run sees the request and the
  target file's signatures (`do.contract_and_shape`) and writes one `tests/red_<id>.py`; gruntly runs it on the starter
  and keeps it only if it fails. Step 2: the usual run with that file added to the acceptance. Block: `red test: written by
  a separate child, fails before and passes after (unproven: model-written)`. With `--samples`, it ranks candidates.
- Tests: the red test passes on the starter → dropped with a note; fails → kept and in acceptance; the fix child cannot
  edit it (scope).
- Measure: false-pass rate on tasks without existing coverage, child-only bench.

## M4. The benchmark (backlog 7)

### 4.1 Marginal cost and the missing columns (no spend)
- `run_bench.report()` (`run_bench.py:211-251`): `marginal $` = cost − `cost_model.FRESH_TURN1` (the $0.045 fresh-session
  floor) and `vs alone (marginal)`; `reviewer $`; `takeovers` (parent Edit/Write/MultiEdit calls after the first gruntly call,
  from `analyse()`, `run_bench.py:113-146`); `holdout` (present / pass). A `--report-only` flag re-renders saved rows:
  re-render `benchmark-forced-oneflow`, `benchmark-subagent`, `benchmark-haiku-alone`.
- Headline metric (related work, row 2): **cost-of-pass** = mean cost ÷ pass rate per arm (Cost-of-Pass; false passes and
  takeovers fall into it without a separate rule), with a marginal variant after the floor; and a resolved-vs-cost curve
  with a per-task cap (SWE-Effi's AUC under a budget; HAL's Pareto view), so an arm that wins on means but loses on
  reliability shows it.
- `docs/benchmarks/README.md`: the marginal-cost rule, cost-of-pass, the arm list, "no quality claim under n = 20".

### 4.2 The deep-session arm (script free; the run about $3.50, on approval)
- `bench/run_deep_bench.py`: one repository from all `bench/tasks/*` (each starter in its own package directory, hidden
  tests kept outside); two sessions (alone; the one-call flow with a parent-written holdout), each primed by one prompt that
  reads about 150k tokens of files (`claude -p --session-id UUID`, then `--resume UUID` per task); the ten tasks in the same
  order, within the 1-hour cache window; hidden tests judged after each task; per-task cost = Δ `total_cost_usd` between
  calls (checked once against the transcript's usage). Columns: cost per task, parent turns, context growth, hidden-test
  pass, takeovers. Dry run with the fake child and `--max-turns 1` first (cents).
- Spend: about $0.60 priming per session + 10 tasks × 2 arms ≈ $3.50 (investigation §9). Asked for separately.

### 4.3 Tasks of 8+ alone-turns from real repositories (building free; runs on approval)
- `bench/make_real_tasks.py`: from pinned commits of the user's repositories (Contri, kaira-show, Gruntly-Website) and two
  public Python ones (requests, click): starter = the parent commit, hidden tests = the fix commit's tests, request = the
  issue or commit message; `bench/validate_tasks.py` proves starter red and reference green. Target ten tasks whose alone run
  takes 8+ turns (one alone run each to confirm: about $8).
- A quality claim needs n ≥ 20 per arm: 20 runs × 2 arms × $0.6 to $1.2 ≈ $25 to $50. Pilot first: 2 tasks × 2 arms × 2
  repetitions (about $5). Each stage asked for separately. The child-side variants (`--samples`, the escalation chain,
  `--red-first`) are compared first on the child-only bench at $0 parent cost; only the winner joins the paid arms.

## Also considered after the related-work pass (`docs/related-work-2026-11-11.md`), not in this plan
- A free local model as a first-pass reviewer that may only reject: reviewer dollars are already $0.0005–0.0007 a step,
  and the Draft-Model Gate paper shows a 4B gate lowering task success when it vetoes.
- Learning from past runs (EcoAssistant's demonstrations, NVIDIA's SLM fine-tuning): needs hundreds of passed runs first.
- Pipelining supervised steps against the reviewer (Dynamic Speculative Agent Planning): saves wall time, not money.
- RTK-style tool-output compression: the user's own sessions, not gruntly; worth a measured try with the transcript
  analysis, ceiling bounded by the 3–33% that tool results make of context growth.

## Risks
- 1.2: the injected command's time limit may cap `/gd` below a slow child's run; then one-turn `/gd` needs a settings change
  or the hook that this plan leaves out.
- 2.3: selection by visible tests alone can pick a false pass; the holdout and the unproven line are the guard, and N stays
  at 3; hosted rate limits (the proxy's 429 handling) bound the parallel samples.
- 3.1: cache reads depend on where Claude Code puts its breakpoints; measured, with the caching-off fallback already costed.
- 2.1: a wrong holdout fails a correct run; the block shows the holdout's failing tail, so the parent sees its own mistake.
- 3.2: no history on a fresh machine keeps today's constants until twenty runs exist.
- M4: no quality claims until 4.3 is funded; until then the numbers are cost numbers on small tasks.

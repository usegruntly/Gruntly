# Changelog

## Unreleased
- Parent adapters (issue #11): the parent side of a delegation is now an interface like the child side (`src/gruntly/parents/`): `detect`, `command(task, mode, model, provider, structured)`, `parse`, `capabilities`, `cancel`, plus `run` which writes the harness's files, gives it the task on stdin and reads the result. A parent has two prompt categories in one module (`parents/prompts.py`): **delegating** (the lean setup; the prompt is byte-identical to the one the benchmarks measured, now also named `agent.LEAN_PROMPT` for older callers) and **working** (the harness as shipped, plus one short instruction; an escalation is a working parent that is told what the local child tried). `ParentCaps` records what a harness can do of the lean setup (replace its system prompt, leave only a shell tool, allow only `gruntly` commands, switch off extensions, report usage and cost) and `ParentCommand.notes` says what a launch could not do, so nothing is claimed that a harness does not. Claude Code moved behind it with no change: a test pins the exact command line of both modes, and the launcher (`gruntly agent`, `agent.run_agent`, `agent.lean_command`) gives the same result. A harness that is not installed is now an error that says so (exit 127), not a traceback. The result markers moved to `gruntly/markers.py`.
- Cost accounting for any hosted child (issue #10): the proxy now reads the `usage` of every response it carries (OpenAI-shaped, Anthropic-shaped, plain JSON or streamed, read from the head and tail of a stream) into a meter, so a hosted child's tokens and dollars are known whatever harness it runs in. A response without usage counts as `missing`, not zero. Dollars come, in this order, from the provider's own report (OpenRouter's `usage.cost`), a price file (`~/.config/gruntly/prices.toml`, `<project>/.gruntly/prices.toml`, or the packaged `prices.toml`, which holds only the measured Claude rates), or the provider's cached model listing (OpenRouter, Together). Otherwise the price is UNKNOWN: the run's `child_usage.json` says `cost_unknown`, benchmark totals count it as zero and the report lists those runs as lower bounds. A local child costs no API dollars and says compute is not priced. The result's `child` block gains `cost_source` and `cost_unknown`; the parent still never sees dollars in the block's cost line. Tests: parsing of both shapes, the proxy meter against a fake upstream, price order, broken files, the packaged Claude rates against a recorded Haiku run to the cent-fraction.
- `gruntly verify [provider] [--model ID] [--json]` (issue #9): a live check of each provider that has a key and each local server that answers: does the model list come back, and does one tiny call (`Reply with the single word: ok`, 8 tokens at most, no code of yours) work? One line each: ok, or no key, bad key, rate limited, model not found, bad request, server error, timeout, unreachable (a local server that is off says `not running`, which is not a failure of the default sweep). Keys are scrubbed from every message, some providers echo them. The last result is kept and shown as `CHECKED HERE` by `gruntly providers`. `gruntly models` now keeps a day-old copy of a hosted provider's list (`--refresh` asks again; local servers are always live), shows context size and price when a listing gives them (OpenRouter, Together, Fireworks, Mistral, Groq), and accepts the local server names (ollama, llamacpp, vllm). Tested against a fake OpenAI-compatible server for every outcome; no live run yet (needs keys).
- Provider catalog (issue #8, 2026-11-14): providers are data in `src/gruntly/data/providers.toml`, no longer hard-coded. Hosted: gemini and nvidia (unchanged, the only two verified live), openrouter, openai, deepseek, groq, together, fireworks, mistral, cerebras, xai (from documentation, `verified = false`, no model ids kept: pick one with `gruntly models NAME`, then `gruntly use NAME MODEL`; a run with no model says so instead of failing in the proxy). Local servers: lmstudio, ollama, llamacpp, vllm (`provider = "ollama"` means the local provider at Ollama's address unless the spec sets an endpoint). `~/.config/gruntly/providers.toml` and `<project>/.gruntly/providers.toml` add providers or override single fields (a later file wins field by field); a broken file is reported and ignored. New `gruntly providers [--json]` lists them with key status and never a key.
- Real-fix and rename checks of the final escalation rules (2026-11-13, $0.84 in all; `docs/benchmarks/lean-esc-v3-rename.md`, `lean-esc-real.md`). A fresh `rename_domain` run passed 2 of 2 with no escalation ($0.047 and $0.045), so the names-check fix holds on the case that misfired. On the 8 real click fixes the lean parent with a Haiku child passed 1 of 8 in the lean phase, the same as before the scope was opened; one run escalated (`helpformatter`: the child tripped the test-weakening gate twice after a changelog-only first round) and was rescued for +$0.174, so 2 of 8 in the end, against 4 of 8 for Sonnet alone. Cost per run was lower ($0.094 against $0.134) but cost per correct task higher ($0.375 against $0.268). The rare, count-based escalation did what it was built to do (no needless escalation in 18 runs of the final rules) but cannot catch what the real tasks mostly fail on: edge cases the child missed while its tests passed (`short_help` 34 of 36 hidden cases, `show_envvar` 667 of 676). Caveats: one run per task, the lean prompt is not told the check or the file scope the alone arm is told, and 4 of the 8 tasks fail in both arms. The next lever for real tasks is stronger verification (a parent-written holdout test), not more escalation.
- Stuck detection and a rare, measured escalation (2026-11-13). A child is stopped early when it makes no progress, where progress means a diff it has not produced before (`gruntly/escalation.py`): no new diff for `stall_s` after its first edit (default 240 s), no edit at all for `first_edit_s` (420 s), edits it undoes three times, or more than `max_calls` tool calls in one attempt (80); the clocks never run shorter than 2x and 3x `no_progress_s`, which gruntly already sizes to a slow model's own request time. A failed run's result carries `escalation: {class, why, rounds, eligible}` (stuck, hard, gave_up or slow), and `rounds` is counted across follow-ups. The block says `escalation: recommended` only when all of these hold: the policy is on (`[escalate] when = "hard"` or `GRUNTLY_ESCALATE=hard`; off by default, there is no looser mode); a second round with guidance has also failed (or passed with the request still uncovered); and counting shows part of the ORIGINAL request is still uncovered by the work of all rounds so far (`coverage.cumulative_patch` against the first request, carried along follow-ups in `request.json` and `lineage.json`). The lean prompt then tells the parent to reply `GRUNTLY-FALLBACK`, and `gruntly agent` runs a full session with the normal Claude Code system prompt and tools (the fallback used to allow only `gruntly` commands) and tells it what the local model tried. Development A/B: `bench/run_bench.py --arms lean_esc` runs the lean parent with the policy on; the hidden tests run after the lean phase (what `lean` alone would have scored), an escalation runs the `alone` arm's session on the tree as it stands, and they run again, so every row carries both outcomes and both costs (`docs/benchmarks/lean-esc-multi.md`). First A/B, 10 runs (5 long tasks x 2, Sonnet lean parent and Haiku child, $1.02) with the first rule, a failed second round alone: 5 of 10 runs escalated, 2 rescued (`settings_refactor`) and 3 needless (the parent had asked for more than the hidden tests needed, and the child's empty diff or gate trip was taken for inability); escalation cost $0.553, and the cost per correct task went from $0.059 before to $0.102 after, equal to Sonnet alone ($0.105), so that rule was not worth it. Adding the persisting-gap condition keeps both rescues and drops all 3 needless ones when replayed on those 10 runs, which is the data the rule was shaped on, so it still needs a fresh run. Calibration of the stall clocks, from the 77 recorded Haiku child runs: none of the 15 failures looped and the median failure took 11 tool calls and 37 s, so they will not fire on a Haiku child; they are for slow local children, whose records were not kept, so their defaults are conservative guesses. Confirmation run with the final rules and the scope open (`docs/benchmarks/lean-esc-v2.md`, 10 runs, $0.61): all 10 passed in the lean phase at $0.044 per correct task (Sonnet alone: $0.105), `settings_refactor` and `inventory_reorder` included (2 of 2 each, $0.026 to $0.076 a run). 2 runs escalated, both `rename_domain`, both needless: the 'names the request asks for that exist nowhere' check read the name being renamed away (`customer_label`) as missing, which is what a correct rename leaves. That check no longer grounds an escalation (it stays a hint in `flags:`); only counts of files and parts do (`coverage.STRONG`). Replayed on all 20 recorded `lean_esc` runs the final rule drops all 5 needless escalations and keeps the 2 needed ones (`settings_refactor` in the first A/B, before the scope was opened for it) with no false alarm on the 15 runs that never escalated; the rule was shaped on those runs, so a fresh `rename_domain` run is still the check that the fix holds.
- A request that lists three or more parts, or says every other module / everywhere, now runs with the whole project in scope (`agent.open_scope`), and a follow-up may touch the files it names or, for such a request, the whole project (`agent.widen_scope`). Found on 2026-11-13 by the escalation A/B: the first run's brief said `Change only: inventory/service.py` and every follow-up inherited the first run's file scope, so on the long multi-file tasks the child did one part and reported the rest as out of scope, or came back with an empty diff. That, not the child's ability, was the main reason the lean parent with a Haiku child failed `inventory_reorder` and `settings_refactor` in the 2026-11-12 batch (0 of 4). With the scope open, `inventory_reorder` passed 2 of 2 in the lean phase. The diff-size, test-weakening and new-dependency gates and `deny_paths` still apply. Replaying the A/B before this scope rule was extended to 'every other module' requests: `settings_refactor` (one paragraph, no numbered parts) was still scoped to the one file it named.
- Coverage facts in the result block (`src/gruntly/coverage.py`, 2026-11-13): from the request and the diff alone, with no model, gruntly counts how much of a request a change covers and adds short lines to `flags:`. A request that lists N parts (numbered, lettered or labelled `Storage:` / `API:` / `CLI:`) while the diff touches one source file; a file the request names that the diff never touches; an 'every other module' request where the diff touches under half of the source files in its directories; names the request asks for (snake_case, CamelCase, backticked) that the diff does not add and the repo does not contain; a diff that changes only non-code files (a changelog) for a request about code. A passed child that edited files but ran no test of its own is a `review_hint` (`trace.concerns`). The lean prompt now says to put exactly what the flags name into one follow-up. Replayed on the recorded lean runs of 2026-11-12 (the rules were shaped on those runs, so this is a check, not a test): the 4 failed long-task runs and the 2 changelog-only real-fix runs are flagged; the 6 passing long-task runs and the passing real run are not. The 3 empty-diff failures were already reported as failed, and the one false pass (an error-message edge case, 2 of 676 hidden cases) cannot be found by counting. The lean parent of those runs already noticed the gaps in its replies and the child still failed the follow-ups, so this makes the detection reliable; it does not make the child finish. Not yet re-measured: no benchmark has run with the new flags and prompt.

- Plugin 0.12.0, the second and third milestones of `docs/plan-2026-11-11.md`.
- `gruntly agent-run --holdout PATH 'request'`: a test the parent writes for a behaviour the existing tests do not check, in the same call (`<<'EOF'` heredoc on stdin, or a file written first). The child never sees it (it is kept out of the child's worktree) and a pass needs it green; a failure tells the child only which tests failed, never what they assert. The block says `holdout: pass (...)`, and a pass the holdout proves is no longer called UNPROVEN. With `--supervised` the holdout runs once at the end, after every step is approved, and a red holdout fails the task whatever the reviewer said (`hide` is the new spec field that keeps a file out of the children's worktrees without gating each step on it). The skill, the hook text, the guide and the snippet teach it.
- `gruntly agent-run --review [--reviewer model[:effort]]`: after a pass, one review of the diff and the child's report by your model (Sonnet at low effort by default, caching off, about $0.007) outside your session, with the rules, CLAUDE.md / AGENTS.md and the request as a byte-stable system prompt file. On FIX the same call sends the reviewer's words to the child once and reviews the combined change again; the block carries both verdicts and the review cost, and the gates' verdict is never changed by a reviewer. Off by default.
- Supervised reviews: the stable context (the reviewer's role, the rules, CLAUDE.md / AGENTS.md, the task, and for the step reviews the approved plan) is now a `--system-prompt-file` written once per task and never changed, so a provider's cache can serve it; the plan review (one Sonnet call) skips the cache, the step reviews use it. Each review's tokens (input, cache read, cache write) are recorded in `costs.json` and the block says how many tokens came from cache. Windows: no more `.cmd` quoting limits on the system prompt.
- Child time budgets grow with the child's own history (`gruntly/speed.py`): after 8 recorded runs of a harness and model, the run budget is 1.5 x the 90th percentile of its wall times (up to 1800 s) and the idle limit 3 x its median seconds per request (up to 300 s), for runs and supervised steps; they never drop below today's defaults (900 s a run, 600 s a step, 120 s idle) and a non-default value in your own config wins. `gruntly stats` shows them.
- `/gd` no longer names a wait: `gruntly do` sizes it itself, 100 s by default and up to 540 s when `BASH_DEFAULT_TIMEOUT_MS` is raised in Claude Code's settings. Measured with Haiku probes (2026-11-12): an injected command of 5, 30 and 100 s stayed one turn; 150 s was moved to the background and the model got only "the background command finished", never the block; with the variable at 600000 the same 150 s stayed one turn. (The first version of this milestone set `--max-block 540`, which would have hidden the block for any child slower than 120 s.)

Twelve fixes of pallets/click are in (all checked; four are marked `vague` because the maintainers' entry is one line, and `run_bench.py --real` leaves those out); fix commits from after a model's training cutoff cannot have been memorised. `run_bench.py` runs them as bucket R. ## 0.3.0 - 2026-11-08

Slim child profiles, evaluate & fix, and foreground waiting.

- **Profiles** (`profile: auto|typist|worker|default`): the local model no longer pays for its harness's full system prompt and tool set. `typist` (a few small, literally named files) inlines the files in the prompt and offers only file-writing tools; `worker` adds list/search/read for tasks where the files cannot be named; `default` is the old behaviour. `auto` picks from the scope. Measured on OpenCode (`docs/benchmarks/child-bench.md`): ~70% fewer child tokens per run (79% on the small tasks) and ~44% less wall time at equal hidden-test pass rate (68% against 62%). A slim run on Qwen Code used ~2.2k input tokens per request instead of ~14k. Slim profiles need an 8k (typist) or 16k (worker) context window instead of 32k.
- **Evaluate & fix** (`self_check: false`, the default): the child has no shell and is told not to run tests. gruntly runs the acceptance command and every other gate and feeds the failure straight back as the next attempt; the parent never sees intermediate failures. In the benchmark, letting the child run its own tests bought nothing.
- **No shell, no waste:** OpenCode runs a one-line custom agent with only the tools the profile needs and no AGENTS.md, `~/.claude` skills or plugin discovery; Qwen Code runs `--bare`, which also drops its extra ~7k-token memory request. Per-request input tokens are recorded and shown in `gruntly stats`.
- **Foreground waiting:** `gruntly run` now blocks up to `--max-block` seconds (default 240) and returns a ~150-byte `{"status": "running"}` if the run is longer; `gruntly wait <run>` blocks again. The skill says never to use `run_in_background`, which ended the parent's turn and replayed the whole conversation in a second session to read a 300-byte result. A worker that dies without a result is reported instead of hanging.
- **Findings:** no profile fixes false passes (gates green, hidden tests red); they come from briefs and visible tests that omit behaviour the hidden tests check. On vague briefs every arm, including the stock harness, failed, so the parent keeps writing precise briefs. See `docs/benchmarks/child-bench.md`.
- **Fixes found while testing:** OpenCode needs each enabled tool's permission granted explicitly or the model gets no tools and pastes code into its reply; Qwen Code's `edit` needs `read_file` to have been called first.
- **Benchmarks:** Sonnet-parent results added (`docs/benchmarks/benchmark-v2-sonnet.md`). Earlier benchmark floors are not comparable with new runs: the claude.ai connectors (~50 tool schemas per session) were disabled afterwards.
- Not done: a live Qwen Code benchmark (one slim run measured), the last 11 vague-brief runs (the machine ran out of memory), Hermes, sandbox level 1 on Linux.

## 0.2.1 - 2026-11-07

Fixes found by benchmark v2 (see `docs/benchmarks/benchmark-v2.md`).

- A holdout file outside the repo, or missing, now fails at spec time with a clear message instead of a raw git error after the child's work.

## 0.2.0 - 2026-11-07

Rework after a cost audit of the 0.1.0 benchmark (delegating cost 70% more than doing the work alone; most of it was fixed overhead in the parent's turns, not escalations).

- One-call flow: `gruntly run --apply-on-pass` applies a passing patch, re-verifies in your tree only if it changed, reverses the patch if that check fails, and cleans up the worktree.
- Result schema 2: a pass is ~300 bytes (was ~1 KB). All child-written text (summary, test output, handoff) is under one `untrusted` key and only on non-passes; `child_summary`, `timing` and `child_usage` are gone from the parent's view.
- New gates and signals: `holdout` (parent-written tests the child never sees), `regression` (run the wider suite), red-before-green warning when acceptance already passes at the base, `review_hint`.
- Preflight refuses a model context under 32k tokens (`allow_small_ctx` overrides); queue waits are capped at the run budget and say who holds the slot.
- Plugin: skill cut from ~1,200 to ~230 words (full manual via `gruntly guide`), MCP tools cut from 7 to 2, MCP install pinned to a release tag.
- `gruntly stats` keys by harness/model/context and recommends `delegate`, `avoid` or `unknown`.
